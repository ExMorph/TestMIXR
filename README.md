# Material Accumulation on Surface

Реализация механики накопления материала на плоской поверхности с изменением геометрии Mesh.

Презентация работы - https://youtu.be/DVKpQfJJWkQ

## Управление

| Клавиша | Действие |
|---------|----------|
| W/A/S/D | Перемещение зоны воздействия |
| Пробел (удерживать) | Накопление материала |
| R | Сброс поверхности |

## Архитектура

Решение разделено на6 классов с чёткими ответственностями:

```
SurfaceController (MonoBehaviour) — единственный точка входа
    ├── HeightMapData       — data layer: float[] высот
    ├── MeshGenerator       — генерация базовой плоскости
    ├── HemisphereZone      — полусфера: позиция, радиус, пульсация
    ├── MaterialAccumulator — логика накопления
    └── MeshUpdater         — связь data → mesh
```

## Способ хранения материала и обновления Mesh

**Хранение:** Высота материала хранится в плоском `float[]` массиве (`HeightMapData`), где каждый элемент — высота над базовой плоскостью в одной точке регулярной сетки. Массив имеет размер `(segmentsX + 1) * (segmentsY + 1)` и полностью отделён от отображающего Mesh. Индекс вычисляется как `z * resolutionX + x`.

**Обновление Mesh:** Каждый кадр `MeshUpdater` записывает значения из `float[]` в `Vector3[].y` предварительно созданного Mesh. Массив вершин создаётся один раз при инициализации и переиспользуется — единственная аллокация происходит при записи `_mesh.vertices = _vertices` (внутреннее требование API Unity). После обновления вершин пересчитываются нормали через `RecalculateNormals()`.

## Алгоритм накопления

1. При зажатом пробеле, каждый кадр вычисляется `heightDelta = speed * Time.deltaTime` — зависимость от FPS исключена.
2. Если зона перемещалась, траектория от `PreviousPosition` до `Position` разбивается на промежуточные точки с шагом `min(cellSizeX, cellSizeZ)`. Это гарантирует непрерывный след при любой скорости.
3. В каждой промежуточной точке для каждой вершины сетки в bounding box зоны вычисляется высота полусферы `y = sqrt(R² - d²)`.
4. Если `текущая_высота + heightDelta < высота_полусферы` — материал добавляется. Иначе высота ограничивается формой полусферы. Материал **только добавляется**, ранее накопленный сохраняется.

## Форма полусферы

Высота в точке `(x, z)` вычисляется аналитически:

```
y = sqrt(R² - dx² - dz²)
```

где `dx = x - centerX`, `dz = z - centerZ`, `R` — текущий радиус. Если `dx² + dz² >= R²`, высота = 0.

## Радиус

Радиус пульсирует по формуле:

```
R(t) = BaseRadius + Amplitude * RadiusCurve(t % period)
```

`AnimationCurve` задаёт форму пульсации. Период = `1 / Frequency`.

## Оптимизации

- **Bounding box:** Вместо перебора всех вершин меша вычисляется диапазон индексов сетки, попадающих в радиус зоны. При радиусе = 1 и поверхности 20x20 с сеткой 100x100 проверяется ~10% вершин.
- **Без аллокаций:** Массивы вершин и треугольников создаются один раз. `float[]` heightmap не пересоздаётся. Единственные аллокации — `mesh.vertices = _vertices` (внутреннее требование Unity API).
- **Интерполяция траектории:** Шаг интерполяции = размер ячейки сетки, что гарантирует перекрытие всех вершин при движении на любую скорость.

## Фактически затраченное время

~4 часа. На этапе написания кода использовался AI-ассистент (OpenCode).

## Ограничения решения

1. **Квадратная сетка:** Разрешение по X и Z задаётся раздельно, но поверхность — регулярная сетка. Невозможна адаптивная детализация (больше вершин в зоне воздействия).
2. **Одностороннее накопление:** Материал добавляется только снизу вверх. Невозможно «срезать» или «переместить» уже накопленный.
3. **Нет коллизий:** Зона не взаимодействует с другими объектами сцены.
4. **Одна поверхность:** Решение рассчитано на одну плоскость. Множественные поверхности потребуют дублирования или рефакторинга.
5. **Нет морфинга/сдвига вершин по XZ:** Вершины смещаются только по Y. Нет деформации горизонтальной плоскости (растяжение, сдвиг).
6. **Performance при высоком разрешении:** `RecalculateNormals()` — O(N) по вершинам. При very высоком разрешении (500+) может быть заметен на каждом кадре.

## Возможные улучшения

1. **Compute Shader:** Вынос накопления и обновления вершин на GPU — снятие нагрузки с CPU, поддержка разрешений 1000+.
2. **Chunked mesh:** Разбиение поверхности на чанки с LOD — обновлять только те, что рядом с зоной.
3. **Multi-zone:** Поддержка нескольких зон одновременно через Merge высот.
4. **Визуализация зоны:** Отображение радиуса через LineRenderer или Gizmo в Game view (не только Scene view).
5. **Saving/Loading:** Сериализация `float[]` в файл для сохранения состояния.
6. **Biome / текстуры:** Маскирование по высоте для отображения不同的 материал (песок, камень, снег).
